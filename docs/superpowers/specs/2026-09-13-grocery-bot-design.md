# Продуктовый бот: спека (13.09.2026)

Telegram-бот, который по фразе «собери корзину на карбонару, спагетти есть» подбирает рецепт, собирает корзину во ВкусВилле и кладёт её в аккаунт владелицы. Владелице остаётся открыть приложение ВкусВилла и оплатить.

## 1. Цели и границы

**Делает**

- Рецепт по запросу: фото, ингредиенты, шаги, ссылка на источник. Источник обязателен, рецепт «из головы» модели запрещён.
- Корзина: разбор рецепта на покупки минус то, что есть дома, подбор товаров в каталоге ВкусВилла, таблица «ингредиент → товар → цена → сумма» на подтверждение.
- Правки словами в диалоге: «сыр подешевле», «яйца не надо», «удвой».
- Размещение корзины в аккаунт владелицы через браузер на сервере, проверка наличия на её складе доставки, замена отсутствующего на аналоги с подтверждением.
- Память: что есть дома всегда, любимые и нелюбимые товары, прошлые замены.
- Вход в аккаунт ВкусВилла по СМС прямо из Telegram, повторный вход по запросу бота при протухании сессии.

**Не делает**

- Не оплачивает и не выбирает слот доставки. Это владелица делает в приложении.
- Не работает с другими магазинами (слой «товары и корзина» изолирован, чтобы это стало возможно позже).
- Не генерирует картинки. Фото только из источника рецепта.
- Не обслуживает других пользователей: отвечает только владелице по Telegram ID.

## 2. Архитектура

```
Telegram (long polling)
   │
   ▼
bot/  (Node.js)  ── маршрутизатор: команды входа / код СМС / обычное сообщение
   │
   ▼
engine/  ── адаптер к модели. v1: Claude Code headless (`claude -p`, подписка)
   │        интерфейс: run(chatId, text) → {reply, photos[], sessionId}
   │
   ├── MCP vkusvill (HTTP) ── поиск, детали, аналоги, рецепты, ссылка на корзину
   ├── WebSearch / WebFetch ── рецепты из интернета, когда во ВкусВилле нет
   ├── Read / Write в memory/ ── память: pantry.md, preferences.md, history/
   └── Bash: node tools/cart.mjs <link>  ── Playwright, размещение корзины
                │
                ▼
         browser/  (Playwright, persistent context с сессией ВкусВилла)
```

Компоненты и их зоны ответственности:

| Компонент | Что делает | От чего зависит |
|---|---|---|
| `bot/` | Принимает сообщения Telegram, фильтрует по владелице, ведёт состояние «ждём код СМС», отправляет текст и фото | Telegram Bot API, `engine/`, `browser/login` |
| `engine/claude-code.mjs` | Запускает `claude -p` с системным промптом, MCP-конфигом, списком разрешённых инструментов и `--resume` для продолжения сессии чата | CLI Claude Code, токен подписки |
| `engine/api.mjs` (резерв) | Тот же интерфейс поверх Anthropic API. Пишется только если подписочный путь закроется | `@anthropic-ai/sdk` |
| `tools/cart.mjs` | Открывает ссылку `share_basket` в сессии владелицы, читает страницу корзины, возвращает JSON: позиции, цены, флаги «нет в наличии», итог | Playwright, профиль браузера |
| `tools/login.mjs` | Вход по номеру телефона: вводит номер, ждёт код из файла, вводит код, сохраняет сессию | Playwright |
| `memory/` | Markdown-файлы, которые модель читает и правит сама | файловая система |

## 3. Движок: Claude Code по подписке

Каждое сообщение владелицы превращается в вызов:

```
claude -p "<текст>" \
  --model sonnet \
  --resume <session_id чата> \
  --append-system-prompt-file prompts/system.md \
  --mcp-config mcp.json --strict-mcp-config \
  --allowedTools "mcp__vkusvill__*,WebSearch,WebFetch,Read,Write,Edit,Bash(node tools/cart.mjs *)" \
  --output-format json
```

- Рабочая директория процесса: `workspace/` с `memory/` и `tools/`. Модель видит только её.
- Токен подписки в `CLAUDE_CODE_OAUTH_TOKEN` из `.env` (получен командой `claude setup-token` на компьютере владелицы).
- Сессия чата живёт до команды «новый заказ» или 12 часов тишины, потом новая. Так контекст не разрастается.
- Один вызов за раз: очередь в `bot/`, пока идёт ответ, следующее сообщение ждёт. Промежуточный статус «ищу товары…» отправляется через 5 секунд ожидания.
- Фото: модель пишет в ответе строки `PHOTO: <url>`, бот вырезает их и отправляет как картинки, остальное как текст.

Если Anthropic закроет подписочный доступ для headless-вызовов, меняется только `engine/`: интерфейс `run()` остаётся, внутри появляется вызов API с теми же инструментами через MCP-коннектор и веб-поиск. Ориентировочная стоимость на API при ежедневном заказе оценивается отдельно до включения, по правилу «траты только с согласия».

## 4. Системный промпт: правила поведения

Ключевые правила, которые входят в `prompts/system.md`:

1. **Рецепт только с источником.** Порядок: рецепты ВкусВилла через MCP (там уже привязаны товары) → веб-поиск по кулинарным сайтам, взять 2–3 версии, сверить тип теста, температуру, время, дать ссылку на выбранную → рецепт владелицы, если она прислала текст или ссылку. Если источники расходятся в ключевом моменте, сказать об этом.
2. **Несуществующие блюда.** Если запрос противоречив («свиные крылышки»), сказать прямо и предложить реальное.
3. **Товары не выдумывать.** Каждая позиция корзины это конкретный xml_id из поиска. Не нашёл: спросить, а не класть похожее.
4. **Память.** Перед сбором прочитать `memory/pantry.md` и `memory/preferences.md`. После подтверждения заказа дописать замены и предпочтения. Правки владелицы «дома всегда есть X» идут в pantry.
5. **Таблица перед корзиной.** Сначала показать список с ценами и итогом, дождаться «да», потом ссылка и размещение. Правки словами до «да».
6. **Размещение.** После «да» создать ссылку через MCP (до 20 позиций на ссылку, при большем заказе несколько ссылок подряд), запустить `tools/cart.mjs`, прочитать результат. Отсутствующие позиции: искать аналоги через MCP, показать владелице, заменить после согласия.
7. **Ответ владелице.** Коротко, без лишних слов, в конце одна строка: что делать дальше («открой приложение, корзина на 1 840 ₽ лежит»).

## 5. Браузерный слой

`tools/cart.mjs <share_link>`:

1. Открыть ссылку в persistent context (профиль в `browser/profile/`, только для бота, права 700).
2. Дождаться страницы корзины. Собрать позиции: название, количество, цена, признак недоступности (сайт помечает товары, которых нет на складе доставки по адресу владелицы).
3. Вернуть JSON в stdout. Коды статуса: `ok`, `auth_required` (сессия протухла: нет признаков входа на странице), `error` с текстом и скриншотом в `browser/last-error.png`.

`tools/login.mjs <phone>`:

1. Открыть страницу входа, ввести номер, запросить код.
2. Ждать появления файла `browser/sms-code.txt` до 3 минут.
3. Ввести код, убедиться, что вход выполнен, удалить файл. Сессия остаётся в профиле.

Поток входа со стороны бота: `cart.mjs` вернул `auth_required` → бот пишет «сессия ВкусВилла закончилась, пришли код из СМС» и запускает `login.mjs` → следующее сообщение из 4–6 цифр бот пишет в `sms-code.txt` → после успеха повторяет размещение корзины сам. Номер телефона в `.env`.

Первичный вход для разработки: то же самое через бота. Резервный путь: перенос cookies из Яндекс Браузера владелицы в профиль на сервере.

**Открытые вопросы браузерного слоя, проверяются первыми** (см. раздел 8): как именно страница корзины помечает недоступные товары; не стоит ли капча на входе по СМС; попадает ли корзина сайта в мобильное приложение.

## 6. Данные и память

Всё в файлах в `workspace/memory/`, модель читает и правит их напрямую:

- `pantry.md`: что есть дома всегда (соль, масло, специи) и временно («спагетти есть», сгорает через 7 дней, дата рядом).
- `preferences.md`: бренды, ограничения по цене, нелюбимые товары, размер порций по умолчанию.
- `history/YYYY-MM-DD.md`: что заказали, какие были замены. Модель дописывает после «да».

Состояние бота (сессии чатов, флаг «ждём код») в `bot/state.json`. Секреты только в `.env`: токен Telegram, Telegram ID владелицы, токен подписки, номер телефона.

## 7. Ошибки и отказ

| Ситуация | Поведение |
|---|---|
| MCP ВкусВилла недоступен | Бот честно говорит «каталог не отвечает», не пытается собрать корзину по памяти |
| Веб-поиск не нашёл рецепт | Просит владелицу прислать ссылку или текст рецепта |
| `cart.mjs` вернул `error` | Отправляет владелице ссылку на корзину вручную (запасной путь: один тап) и скриншот ошибки себе в лог |
| Сессия протухла | Поток входа по СМС, потом автоповтор размещения |
| Claude Code упал или таймаут 3 минуты | Сообщение «не получилось, повтори», сессия чата сохраняется |
| Сообщение не от владелицы | Игнор без ответа |

## 8. Порядок работ и проверки

1. **Разведка браузерного слоя (спайк, до кода бота).** Руками через Playwright на компьютере в сессии владелицы открыть готовую ссылку корзины, посмотреть: разметку недоступных товаров, синхронизацию в приложение, наличие капчи на входе. Результат фиксируется в `docs/superpowers/notes/browser-spike.md`. Если корзина сайта не попадает в приложение, размещение заменяется на отправку ссылки владелице, остальная схема без изменений.
2. **Движок.** `engine/claude-code.mjs` + системный промпт + MCP-конфиг. Проверка: из терминала на сервере запрос «шарлотка» возвращает рецепт с фото и источником, запрос «карбонара, спагетти есть» возвращает таблицу без спагетти.
3. **Браузерный слой.** `cart.mjs`, `login.mjs`, тесты на разбор страницы по сохранённым HTML-снимкам.
4. **Бот.** Telegram, очередь, состояние входа, фото. Тесты: фильтр владелицы, вырезание `PHOTO:`, поток кода СМС.
5. **Деплой на 109.94.** systemd-юнит `grocery-bot.service` по образцу калорийного бота, Playwright с Chromium, `.env`, первый вход по СМС.
6. **Приёмка.** Один настоящий заказ с телефона от фразы до оплаты. Замер расхода подписки через `/usage` за неделю ежедневных заказов.

Тесты: Vitest, как в калорийном боте. Модель в тестах подменяется заглушкой движка, браузер заглушкой `cart.mjs`.
